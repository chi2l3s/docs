Volan failures usually belong to a specific stage. Schema diagnostics appear before generation; compilation failures can indicate a client/runtime mismatch; connection failures concern configuration; constraint exceptions concern data or database state.

Identify the failing stage first. That is faster than changing schema, driver and URL at once. Return an application-level HTTP response and keep the detailed cause in diagnostics.

| Exception | Action |
|---|---|
| VolanConfigurationException | Check JDBC URL, dialect JAR and driver |
| VolanValidationException | Supply required write fields |
| VolanNotFoundException | Handle no match in OrThrow, update or delete |
| VolanRelationNotLoadedException | Add include or avoid reading the relation |
| VolanFieldNotSelectedException | Select the field before reading |
| VolanUniqueConstraintException | Handle a duplicate business key |
| VolanForeignKeyException | Verify the referenced row and delete action |
| VolanConstraintException | Check NOT NULL or CHECK constraints |
| VolanMappingException | Align stored values with schema types/enums |
| VolanConnectionException | Check reachability and pool capacity |
| VolanTimeoutException | Check pool/statement timeout and load |
| VolanTransactionException | Retry only when retryable and callback is safe |
| VolanQueryException | Inspect cause and generated/handwritten SQL |
| VolanUnsupportedException | Change unsupported query shape |

Schema diagnostics use E00xx for lexing, E01xx for parsing and E02xx for semantic validation. The diagnostic includes filename, source frame and a suggested fix where possible. For example, E0209 means a model lacks a primary key, E0224 means relation references are not unique. Provider restrictions can raise E0235.

If generated code fails unexpectedly, first align generator/runtime/plugin versions and regenerate. Do not manually fix generated files. Missing tables mean schema DDL was never applied or the URL points at another database.

Java async failures arrive through CompletionException/ExecutionException; inspect the cause. Distinguish a business conflict from a transient connection or retryable transaction failure. Avoid retrying every exception blindly.

Migration edited/missing/unfinished history is a deployment stop, not an ordinary transient query failure. Follow [recovery](/v0.1.0-alpha.2/en/migrations).

## Missing rows and write conflicts

`findUnique` can return null without an error: no row matched. `findUniqueOrThrow` turns that state into `VolanNotFoundException`. Choose based on the operation's meaning and handle absence once at the service boundary.

For `VolanUniqueConstraintException`, inspect the business key and concurrent writes. An `exists` check cannot prevent another transaction from inserting between the check and create. The database constraint remains the final uniqueness check, and the application must explain that conflict.

`update` and `delete` also throw `VolanNotFoundException` when no row matches. If absence is expected and only an affected count is needed, use the matching `*Many` method: an empty set returns `0L`.

## Result access failures

`VolanRelationNotLoadedException` means code accessed a relation the query did not load. `VolanFieldNotSelectedException` means it accessed an omitted projection field. Fix the query shape or DTO fields rather than blindly repeating the query.

For `VolanMappingException`, compare field types and actual data. An enum value absent from the schema or time text written by manual SQL in an incompatible format can cause mapping to fail. Capture a minimal example with the schema, operation and appropriately redacted data.

## Check connections in order

Verify the JDBC URL, provider, dialect module and driver, then server availability and credentials. For SQLite, check the absolute file path and working directory. A missing-table error calls for verifying that migrations ran against this same database.

Do not retry every exception. A wrong field, unloaded relation or invalid schema will not improve with another query. For temporary write failures, consider whether the previous attempt may already have completed and inspect state by a business key when necessary.

## What to retain for diagnosis

Retain the exception type, operation, runtime and generator versions, provider, message and `cause` chain. Unloaded-data errors expose `model` and `relation`, or `model` and `field`. The `constraint` property on `VolanUniqueConstraintException` and `VolanForeignKeyException` can be `null`: drivers do not always report a constraint name. Do not require that property to recognize the conflict itself.

`VolanTransactionException.retryable` describes whether a transaction can be attempted again, not whether every application action is safe to repeat. Java exposes it through a getter. Follow the [retry policy](/v0.1.0-alpha.2/en/transactions); an exception message is not a stable business error code.

Before sharing diagnostics, remove passwords, full JDBC URLs containing credentials and sensitive parameter values. Reproduction usually needs the version, a minimal schema, query shape and fictional data with the same types and constraints.
