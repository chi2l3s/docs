CLI из тега `v0.1.0-alpha.2` — инструмент синхронизации базы. Он предоставляет `db pull` и `db push` и требует Java 17+. В [Установке](/v0.1.0-alpha.2/ru/installation) показано, как собрать этот тег и добавить launcher в PATH.

```bash
volan --help
volan db pull --url jdbc:sqlite:./data.db --stdout
volan db push --schema schema.volan --url jdbc:sqlite:./data.db --dry-run
volan db push --schema schema.volan --url jdbc:sqlite:./data.db
```

## Сначала прочитай изменение

`pull --stdout` печатает представимую структуру базы. Без stdout он записывает файл схемы; `--force` разрешает заменить существующий. Сначала сохраняй интроспекцию отдельно, чтобы случайно не заменить своё описание модели.

`push --dry-run` показывает SQL и предупреждения без применения. Выполни его на нужной базе разработки и проверь удаления, новые обязательные поля и ограничения. `--accept-data-loss` принимает изменения с предупреждениями, но не делает их обратимыми.

## Подключение и пути

По умолчанию используется `schema.volan`. Push читает URL datasource, если он не переопределён `--url`. Pull использует `--url` либо `DATABASE_URL`. Для PostgreSQL передай `DATABASE_USER` и `DATABASE_PASSWORD` через окружение.

URL должен иметь JDBC-формат. Относительный путь SQLite зависит от текущего рабочего каталога. Перед применением проверь цель. Направление сравнения и ограничения интроспекции разобраны в [Синхронизации](/v0.1.0-alpha.2/ru/sync).

## Команды этой версии

В alpha.2 нет `init`, `generate`, `format`, `validate`, `migrate` и `--resolve`. Генерируй клиент программой alpha.2 из [Первого запроса](/v0.1.0-alpha.2/ru/quickstart). Версионируемые SQL-файлы применяются через [API миграций](/v0.1.0-alpha.2/ru/migrations).

Preview CLI alpha.3 имеет больше команд и генерирует более новый API. Переключение документации не обновляет зависимости приложения. Используй инструмент и генератор, соответствующие его версии.
