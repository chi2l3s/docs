При создании записи приложение передаёт значения, база проверяет ограничения, а клиент возвращает результат. Это кажется простым, пока в модели не появляются default, nullable-поля и связанные записи. Разберём эти случаи по отдельности.

Фрагменты выполняются внутри приложения с открытым `db` и таблицами [User/Post](/v0.1.0-alpha.2/ru/schema). Используй новую тестовую базу или уникальные email: повторная вставка тех же адресов конфликтует с `@unique`.

## Создай пользователя и получи его ключ

<CodeGroup>
```kotlin Kotlin
val created = db.user.create {
    email = "alice@example.org"
    name = "Alice"
}
println("Created user ${created.id}: ${created.email}")
```

```java Java
var created = db.getUser().create(data -> {
    data.setEmail("alice@example.org");
    data.setName("Alice");
});
System.out.println("Created user " + created.getId() + ": " + created.getEmail());
```
</CodeGroup>

`email` обязателен, `name` nullable, а `id` получает значение из автоинкремента таблицы. Результат — сущность `User`, из которой можно сразу взять выданный ключ. Конкретный номер не фиксирован и зависит от содержимого и последовательности базы.

Наличие свойства в форме записи не означает, что обязательно нужно присвоить все поля. Обязательное поле без default должно быть передано; пропущенное значение с default заполняет база. Если реальная таблица не соответствует схеме, обещанного default может не быть — синхронизируй структуру до запуска.

## Nullable не означает пустую строку

Если имя неизвестно, поле `name String?` позволяет хранить NULL. Это отличается от `""`: пустая строка остаётся значением и попадает под другую логику фильтрации. Выбери одно правило представления отсутствующих данных и используй его последовательно.

Volan проверяет отсутствие обязательных полей при построении вставки. При нарушении unique constraint база отклоняет команду, а runtime сообщает `VolanUniqueConstraintException`. Проверка email через `exists` перед вставкой может улучшить сообщение, но конкурентный запрос всё равно способен создать конфликт.

## Несколько строк через `createMany`

```kotlin
val inserted = db.user.createMany {
    row { email = "one@example.org" }
    row { email = "two@example.org"; name = "Two" }
}
println("Inserted rows: $inserted")
```

`row` описывает одну вставляемую строку. Метод возвращает `Long` — число вставленных строк, а не список `User` и не список выданных id. Если ключи нужны сразу, создавай записи по одной в [транзакции](/v0.1.0-alpha.2/ru/transactions) либо выбери собственный проверенный SQL подходящей СУБД.

В этой версии массовая вставка сохраняет defaults пропущенных колонок, группирует подходящие формы строк и делит их на пакеты с учётом лимита параметров. Все пакеты выполняются одной транзакцией: конфликт в одном из них не должен оставить предыдущие вставленными. Это не обещание одной SQL-команды для любого количества строк.

Внутри `createMany.row` вложенные операции по связям не поддерживаются. Передавай известный внешний ключ как скаляр либо используй [вложенный create](/v0.1.0-alpha.2/ru/writing/nested-writes) для связанного сценария.

## Когда нужен `upsert`

```kotlin
val user = db.user.upsert {
    where { email eq "subscriber@example.org" }
    create { email = "subscriber@example.org"; name = "Subscriber" }
    update { name = "Subscriber" }
}
```

Если строка найдена, применяется update-форма; иначе используется create-форма. В create повторяется email, потому что условие поиска не является автоматически payload новой записи.

Этот upsert использует поиск и create-or-update, а не единый атомарный server upsert. Два конкурирующих запроса могут оба не найти строку и столкнуться при вставке. Уникальное ограничение и обработка конфликта остаются необходимыми. Не описывай этот метод как гарантию отсутствия гонок.

## Создать объект и выполнить побочный эффект

Отправка письма и HTTP-вызов не откатываются вместе с SQL. Если создание пользователя — часть более длинной операции, объединяй только действия с базой транзакцией, а внешнее действие планируй после её успешного завершения. Для надёжной доставки можно спроектировать outbox-запись в той же транзакции; готового автоматического outbox API клиент не добавляет.
