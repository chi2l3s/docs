Тип поля связывает три вещи: значение в базе, свойство сгенерированной сущности и допустимые условия запроса. Например, `views Int` даёт целое число в Kotlin и Java и позволяет сравнивать просмотры через `gt`, `gte` или `between`. У `title String` дополнительно есть поиск по подстроке.

## Скалярные типы

| Volan | Kotlin | Java для обязательного значения |
| --- | --- | --- |
| `String` | `String` | `String` |
| `Int` | `Int` | `int` |
| `Long` | `Long` | `long` |
| `Float` | `Float` | `float` |
| `Double` | `Double` | `double` |
| `Decimal` | `java.math.BigDecimal` | `BigDecimal` |
| `Boolean` | `Boolean` | `boolean` |
| `DateTime` | `java.time.Instant` | `Instant` |
| `Date` | `java.time.LocalDate` | `LocalDate` |
| `Time` | `java.time.LocalTime` | `LocalTime` |
| `Json` | `io.github.thirtyeighttwentysix.volan.Json` | `Json` |
| `Bytes` | `ByteArray` | `byte[]` |
| `Uuid` | `java.util.UUID` | `UUID` |

Для nullable-чисел Java получает boxed-тип, например `Integer` вместо `int`. `DateTime` описывает момент времени, `Date` — календарную дату, `Time` — время суток. Выбирай их по смыслу данных: дата рождения не должна зависеть от часового пояса приложения.

Тип SQL зависит от [СУБД](/v0.1.0-alpha.2/ru/databases). В частности, SQLite не поддерживает `Decimal` и скалярные массивы в схеме Volan. Не считай одинаковый Kotlin-тип обещанием одинакового хранения во всех базах.

## Обязательное значение, null и список

```prisma
model Document {
  id Int @id @default(autoincrement())
  title String
  summary String?
}
```

Этот фрагмент добавляет модель документа. У `title` обязательно есть значение, а `summary` может хранить SQL `NULL`. В Kotlin это `String` и `String?`; в Java nullable-свойство нужно проверить перед использованием.

Суффикс `[]` означает список. У `String[]` это скалярный массив поддерживающей его базы, а у `Post[]` — связь с несколькими публикациями, без колонки-массива в родительской таблице. Nullable-списки `Post[]?` и вложенные списки `Post[][]` недопустимы. Пустой загруженный список уже выражает отсутствие элементов.

## Пропустить поле и записать null — разные действия

В `create` обязательное поле без default должно быть передано. Пропущенное поле с default может заполнить база; для nullable-поля без default возможно SQL `NULL`. Это зависит и от реальной структуры таблицы: клиент не создаёт default во время вставки.

В `update` пропущенное присваивание оставляет колонку как есть. Явное `name = null` очищает nullable-имя. Поэтому при обработке PATCH-запроса сохраняй различие между «параметр не прислали» и «параметр прислали со значением null». Иначе можно случайно удалить данные, которые пользователь не собирался менять.

Условия отсутствия значения пишутся через `name.isNull()` или `name.isNotNull()`, а не `name eq null`. Подробные примеры есть в [фильтрах](/v0.1.0-alpha.2/ru/querying/filtering).

## JSON и бинарные данные

`Json` — обёртка над текстом JSON. Исходная строка доступна через `raw` в Kotlin и `getRaw()` в Java. Volan не превращает содержимое JSON в класс твоего приложения: сериализацию, разбор и проверку структуры выполняет выбранная тобой библиотека.

`Bytes` возвращает байтовый массив. Это может быть небольшой бинарный payload, но тип сам по себе не задаёт разумный размер вложения. Для больших файлов оцени стоимость хранения и передачи отдельно.

## Значения по умолчанию и проверка правил

`views Int @default(0)` задаёт начальное значение, когда поле пропущено. Оно не запрещает передать `-1`. Тип, default и бизнес-валидация решают разные задачи; проверки диапазонов и доступа нужно выразить в приложении и подходящих ограничениях базы.

Атрибуты default, mapping и timestamp разобраны в [справочнике атрибутов](/v0.1.0-alpha.2/ru/schema/attributes). Если набор значений ограничен состояниями вроде `DRAFT` и `PUBLISHED`, используй [enum](/v0.1.0-alpha.2/ru/schema/enums).
