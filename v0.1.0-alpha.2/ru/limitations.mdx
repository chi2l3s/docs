Проверь эти границы до того, как неподдерживаемая операция станет основой приложения. Этот раздел описывает alpha.2; возможности в разработке не входят в её runtime.

## Запросы и результаты

| Сценарий | Текущая граница | Что делать |
|---|---|---|
| Cursor с произвольным `orderBy` | Такая комбинация запрещена | Используй offset для нужного порядка или обход по первичному ключу |
| Top-N детей для каждого родителя в include | `take` ограничивает связанный batch | Для гарантированного отдельного лимита запрашивай детей явно |
| Проекция с произвольным набором полей | Один generated projection class | Читай только выбранные поля и собирай явный DTO |
| Чтение незагруженной связи | Getter вызывает исключение | Добавь include либо убери связь из ответа |
| Конкурентный upsert | Find/create-or-update, без атомарного server upsert | Сохрани unique constraint и обрабатывай конфликт |
| Фильтры и сортировки скалярных массивов | Отложены | Измени модель запроса или используй проверенный raw SQL |
| Типизированный full-text поиск | Не реализован | DDL индекса не означает наличие query API |

## Запись связей

Nested writes удобны для небольшого связанного создания, но не выражают любой граф изменений. Ограничены nested update глубже одного уровня связей, удаление owning-side required relation и записи с неизвестным ключом прародителя.

Для сложной операции раздели шаги и выполни поддерживаемые записи через [транзакцию](/v0.1.0-alpha.2/ru/transactions). Так порядок получения ключей и обновления строк будет виден в коде. Для обязательной связи удаление или disconnect должно сохранять правило схемы: дочерняя строка не может остаться без required parent.

## Имена и схема

Поле `count` конфликтует с агрегатами. Kotlin keywords экранируются не во всех формах generated API. Выбирай безопасное имя клиента и сохраняй SQL-имя через `@map`, когда база уже существует.

Multi-schema models, optimistic `@version` locking, read replicas и sharding сейчас не реализованы. Tenant isolation и soft delete требуют явных условий приложения.

## СУБД и миграции

Интроспекция работает с представимыми структурами и отказывает, если не может сохранить их корректно. Expression/partial indexes, triggers, generated columns, неподдерживаемые таблицы и другие определения могут блокировать pull или планирование. У конкретного provider есть дополнительные [ограничения типов и каталогов](/v0.1.0-alpha.2/ru/databases).

Транзакционные гарантии PostgreSQL и SQLite описаны в [Миграциях](/v0.1.0-alpha.2/ru/migrations). До развёртывания проверяй SQL и существующие данные: транзакция не исправляет логически неверное изменение.

## Async и совместимость

JDBC остаётся блокирующим через futures и перенос средствами корутин фреймворка. Отмена future в alpha.2 не отменяет активный JDBC statement. Потоки и завершение разобраны в [Async](/v0.1.0-alpha.2/ru/async).

Runtime и генератор должны иметь версию alpha.2; при обновлении генерируй клиент заново. До 1.0 API может меняться. Эта версия поддерживает PostgreSQL и SQLite. Плагины сборки, H2, MySQL, MariaDB, coroutine- и metrics-модули Volan относятся к последующей разработке.
