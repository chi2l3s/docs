Типизированный API удобен для обычных операций. Для запроса со специфичной SQL-функцией, нестандартным JOIN или аналитикой можно использовать `rawQuery`. Ты задаёшь SQL и форму результата, а клиент управляет соединением и передаёт значения параметрами.

Ниже — фрагменты с открытым клиентом `db` и уже существующей таблицей `User` из [схемы](/v0.1.0-alpha.2/ru/schema). SQL с двойными кавычками в этих примерах предназначен для PostgreSQL и SQLite. Произвольный SQL не переводится автоматически между диалектами.

## Прочитай список значений

<CodeGroup>
```kotlin Kotlin title="raw-read"
val emailToFind = "alice@example.org"
val emails = db.rawQuery(
    """SELECT "email" FROM "User" WHERE "email" = ?""",
    listOf(emailToFind),
) { row -> row.getString("email") }
```

```java Java title="raw-read-java"
var emailToFind = "alice@example.org";
var emails = db.rawQuery(
    "SELECT \"email\" FROM \"User\" WHERE \"email\" = ?",
    java.util.List.of(emailToFind),
    row -> row.getString("email")
);
```
</CodeGroup>

Первый аргумент — SQL, второй — значения в порядке появления `?`, третий — mapper для одной строки. Результат в этом случае — список email. При отсутствии совпадений список пустой; mapper не вызывается.

`rawQuery` возвращает `List<T>`, где `T` определяет mapper. Он не добавляет LIMIT и не подгружает связи. Если результат может быть большим, ограничение должно быть в твоём SQL.

## Параметр — значение, а не кусок SQL

Один `?` соответствует одному значению в списке. Email вроде `missing' OR 1=1 --` будет передан как строка, а не как условие SQL. Не собирай запрос конкатенацией пользовательского ввода.

Имена таблиц, колонок, SQL-функций и направление сортировки нельзя передать значением параметра. Если приложение позволяет выбрать сортировку, сопоставляй допустимые варианты с фиксированными SQL-фрагментами. Не вставляй произвольный текст из HTTP-запроса в эту часть команды.

В Java `List.of` не принимает null. Для nullable-параметров выбери подходящий список, например `java.util.Arrays.asList(...)`. Сам API принимает nullable-значения; ограничение `List.of` относится к коллекции JDK.

## Nullable-колонки и собственный DTO

```kotlin title="raw-nullable"
data class UserLabel(val email: String, val name: String?)

val labels = db.rawQuery(
    """SELECT "email", "name" FROM "User" ORDER BY "id" LIMIT 20""",
    emptyList(),
) { row ->
    UserLabel(row.getString("email"), row.getStringOrNull("name"))
}
```

`getString` ожидает значение, отличное от SQL NULL. `getStringOrNull` сохраняет отсутствие имени. Аналогично есть typed-accessors для чисел, boolean, UUID, bytes и временных значений. Читай колонку по её SQL-имени или alias из SELECT, а не автоматически по имени поля схемы.

Mapper вызывается для каждой строки. Возвращай из него данные, которые нужны вызывающему коду; не передавай объект `Row` наружу для отложенного чтения JDBC-результата.

## Измени строки через `rawExecute`

```kotlin title="raw-write"
val affected = db.rawExecute(
    """UPDATE "User" SET "name" = ? WHERE "email" = ?""",
    listOf("Alice", "alice@example.org"),
)
println("Updated rows: $affected")
```

Команда возвращает `Long` — количество затронутых строк по данным JDBC. Оно может быть нулём, если email не найден. Для DDL возвращаемое число зависит от драйвера и не означает количество созданных таблиц.

Raw SQL обходит правила сгенерированных форм записи. Runtime не дописывает `@updatedAt`, не проверяет бизнес-условия и не поддерживает DTO автоматически. Условия доступа, timestamp и проверку числа строк задай явно.

## Соединение и транзакция

На клиенте из JDBC builder raw-операция использует его соединение. Внутри `db.transaction { tx -> ... }` вызывай `tx.rawQuery` / `tx.rawExecute`: они выполняются в той же транзакции, что операции репозиториев. Исключение должно выйти из callback, если нужно откатить всю операцию.

Клиент, созданный только из собственного `QueryExecutor` без JDBC runtime, raw SQL не предоставляет. Такой executor описывает другой способ исполнения типизированных операций.

Поведение атомарности, savepoints и повторных попыток разобрано в [транзакциях](/v0.1.0-alpha.2/ru/transactions). Если SQL меняет структуру таблиц, используй проверенную [миграцию](/v0.1.0-alpha.2/ru/migrations) вместо скрытого изменения при обычном запросе приложения.
