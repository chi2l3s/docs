<Info>
Volan 1.0.0. Libraries and build plugins are available from Maven Central.
</Info>

Create a project with JDK 17+ and a Gradle wrapper. This example uses H2 in memory, a reviewed SQL migration and automatic generation. No database server or global CLI is required.

The plugin adds the matching runtime and connects generation to Kotlin compilation. Java applications also need the Kotlin compiler for generated sources. Choose `application { mainClass.set("example.Main") }` for the Java entry point below.

## Schema and migration

```prisma title="schema.volan"
datasource db {
  provider = "h2"
  url = env("DATABASE_URL")
}
generator client {
  provider = "volan-kotlin"
  package = "example.generated"
  javaFriendly = true
}
model User {
  id Int @id @default(autoincrement())
  name String
}
```

```sql title="migrations/20261005000000_initial/migration.sql"
CREATE TABLE "User" (
    "id" INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    "name" VARCHAR(255) NOT NULL
);
```

Compilation creates the client API; it does not create tables. Commit migration SQL and review it before deployment. `DATABASE_URL` is not needed during generation; this example supplies the JDBC URL in code.

## Write and read

<Tabs>
  <Tab title="Kotlin">
    ```kotlin title="src/main/kotlin/example/Main.kt"
    package example
    
    import example.generated.User
    import example.generated.VolanClient
    import io.github.thirtyeighttwentysix.volan.migrate.MigrationDirectory
    import io.github.thirtyeighttwentysix.volan.migrate.Migrator
    import java.nio.file.Path
    import java.sql.DriverManager
    
    fun openDatabase(url: String): VolanClient {
        DriverManager.getConnection(url).use { connection ->
            Migrator(MigrationDirectory(Path.of("migrations"))).apply(connection)
        }
        return VolanClient.builder().url(url).build()
    }
    
    fun insertAndRead(db: VolanClient, name: String): User = db.transaction { tx ->
        val created = tx.user.create { this.name = name }
        tx.user.findFirstOrThrow { where { id eq created.id } }
    }
    
    fun main() {
        openDatabase("jdbc:h2:mem:kotlin-example;DB_CLOSE_DELAY=-1").use { db ->
            println("Saved and read: ${insertAndRead(db, "Ada").name}")
        }
    }
    ```
  </Tab>
  <Tab title="Java">
    ```java title="src/main/java/example/Main.java"
    package example;
    
    import example.generated.User;
    import example.generated.VolanClient;
    import io.github.thirtyeighttwentysix.volan.migrate.MigrationDirectory;
    import io.github.thirtyeighttwentysix.volan.migrate.MigrationJournal;
    import io.github.thirtyeighttwentysix.volan.migrate.Migrator;
    import java.nio.file.Path;
    import java.sql.DriverManager;
    import java.sql.SQLException;
    import java.time.Clock;
    
    public final class Main {
        public static VolanClient openDatabase(String url) throws SQLException {
            try (var connection = DriverManager.getConnection(url)) {
                new Migrator(new MigrationDirectory(Path.of("migrations")), new MigrationJournal(), Clock.systemUTC())
                    .apply(connection);
            }
            return VolanClient.builder().url(url).build();
        }
    
        public static User insertAndRead(VolanClient db, String name) {
            return db.transaction(tx -> {
                var created = tx.getUser().create(data -> data.setName(name));
                return tx.getUser().findFirstOrThrow(query -> query.where(where -> where.getId().eq(created.getId())));
            });
        }
    
        public static void main(String[] args) throws SQLException {
            try (var db = openDatabase("jdbc:h2:mem:java-example;DB_CLOSE_DELAY=-1")) {
                System.out.println("Saved and read: " + insertAndRead(db, "Ada").getName());
            }
        }
    }
    ```
  </Tab>
</Tabs>

## Run

```bash
./gradlew run
```

```powershell
.\gradlew.bat run
```

```text
Saved and read: Ada
```

The migration connection closes before the client pool opens. `DB_CLOSE_DELAY=-1` keeps this named memory database alive between them; data disappears when the JVM exits. The transaction saves and reads on one connection, and `use`/try-with-resources closes the client. For persistent data choose a file or server URL and apply migrations before handling requests.

[Kotlin](https://github.com/thirtyeighttwentysix/volan/tree/v1.0.0/examples/kotlin-basic), [Java](https://github.com/thirtyeighttwentysix/volan/tree/v1.0.0/examples/java-basic). Both projects include database tests and are verified against actual Central downloads by the release workflow. The query guides use a larger User/Post schema; add those models and their migrations before running those snippets.
