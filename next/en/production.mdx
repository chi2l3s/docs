A deployed service needs a clear startup order: validate configuration, bring the database to the required version, open the shared client and then accept requests. Mixing these steps can expose migration failures after traffic has already started.

The decisions below concern Volan connections, database structure and query results. Your application chooses its configuration storage and deployment mechanism.

## Connection configuration

The connected generated client receives JDBC URLs and credentials through its builder. A schema declaration of `env("DATABASE_URL")` does not make it automatically load all application settings. Validate required values at startup so configuration errors appear before a user's first query.

Install the runtime, matching dialect and JDBC driver. Reuse an application DataSource when one already exists and give the pool one owner. With the built-in pool, keep one shared client. Do not create a client for every row or HTTP request.

## Builder settings and pool ownership

These settings belong to `VolanClient.builder()` in Kotlin and Java. Set them before `build()`; changing a builder does not reconfigure an already open pool.

| Method | When omitted | Purpose |
| --- | --- | --- |
| `url(String)` | No URL | JDBC URL; required for a built-in pool |
| `username(String?)`, `password(String?)` | `null` | Credentials passed to the built-in pool |
| `maxPoolSize(Int)` | `10` | Requested maximum connection count |
| `connectionTimeout(Long)` | `30_000L` ms | Waiting for a free connection, not SQL execution time |
| `poolName(String)` | `"volan"` | Built-in pool name |
| `asyncExecutor(Executor)` | `ForkJoinPool.commonPool()` | Java async execution; application-owned executor |
| `dataSource(DataSource)` | Not set | Use an existing application pool |
| `dialect(Dialect)` | Selected from the JDBC URL | Explicit dialect when URL selection is unavailable |

With `dataSource(...)`, Volan creates no pool of its own. Configure size, credentials and timeouts on that DataSource: built-in pool settings do not override them. Dialect selection still requires `url(...)` or `dialect(...)`; a DataSource alone does not select the SQL dialect. Closing the client does not close the supplied DataSource or executor.

With a built-in pool, client `close()` closes that owned pool. Do not give one component responsibility for closing a pool that another still uses.

For SQLite, the built-in pool uses one connection regardless of a positive `maxPoolSize`. This applies to both file databases and `:memory:`.

## Load and limits

Define maximum page sizes and allowed includes in the service. A caller's `take` parameter should not turn into an unbounded table read. Projections select required columns and explicit DTOs fix the shape of a response.

Pools and workers share the database's capacity. Account for multiple service instances and the connections each owns. Connection acquisition, SQL execution and HTTP wait timeouts serve different purposes; one coroutine timeout does not replace all of them.

## Deployment compatibility

Check migration history before applying files, then assess structural drift separately. History tells you which files ran; drift tells you whether the actual structure matches expectations. A manual database change may leave history untouched, so one check cannot replace the other.

A rolling deployment can run several application versions at once. Plan table changes so the older code survives the transition. Removing a column before stopping the old version breaks its queries regardless of the new client's type safety.

## Shutdown

Stop accepting work, then wait for active queries and transactions. Close the client after they finish, then close caller-owned executors, DataSources and registries according to ownership. A cancelled future does not prove JDBC cleanup has completed.

A private in-memory database disappears with its connection. Use a file or database server for data that must survive restarts, with a verified backup process. For nontransactional DDL, prepare a way to inspect and repair partially changed structure before deployment.
