Когда поле имеет конечный набор состояний, enum делает этот набор видимым компилятору. В коде ты передаёшь `PublicationStatus.PUBLISHED`, а не произвольную строку, в которой легко ошибиться. Это удобно для статуса публикации, роли или состояния обработки.

## Объяви состояния

Следующие блоки можно добавить в схему с настроенными `datasource` и `generator`:

```prisma
enum PublicationStatus {
  DRAFT
  PUBLISHED @map("published")

  @@map("publication_status")
}

model Publication {
  id Int @id @default(autoincrement())
  title String
  status PublicationStatus @default(DRAFT)
}
```

В клиенте поле `status` получает сгенерированный тип `PublicationStatus`. Если значение не передано при вставке, применяется default `DRAFT`, предусмотренный в структуре таблицы. Перечисление должно содержать хотя бы одно значение; имена и хранимые строки внутри него должны быть различимы.

## Mapping значения

Имя `PUBLISHED` существует в коде, а строка `published` — в базе. У сгенерированного значения есть `databaseValue`; для примера это `"published"`. В Java такое свойство читается через `getDatabaseValue()`.

Сгенерированный `fromDatabaseValue(...)` сопоставляет хранимую строку с enum. Если база содержит неизвестное значение, возникает `VolanMappingException`. Клиент не подставляет автоматически первый элемент enum и не превращает ошибку в null.

`@@map("publication_status")` относится к имени enum в базе и не переименовывает класс Kotlin. Представление enum зависит от диалекта: PostgreSQL использует нативный enum, SQLite — текстовое хранение. Не полагайся на enum клиента как на единственную проверку данных всех внешних источников записи.

## Фильтры и формы записи

После генерации используй значения enum в формах `create` и `update` и в условиях `eq`, `notEq`, `oneOf`, `notOneOf`. Клиент преобразует их в хранимые строки с учётом mapping. Операторы диапазона вроде `gt` для enum не предлагаются.

Nullable-поле записывается как `PublicationStatus?`. Отсутствие значения проверяется через `isNull()` / `isNotNull()`. Если enum обязателен и не имеет default, его нужно передать при создании записи.

## Изменение enum — изменение данных

Переименование `PUBLISHED` в коде с сохранением `@map("published")` позволяет оставить прежнее хранимое значение. Изменение mapping, наоборот, меняет контракт с данными: существующие строки нужно перевести на новое представление до чтения несовместимым клиентом.

При добавлении состояния продумай порядок развёртывания. Пока часть приложений использует старый enum, она не сможет прочитать новое значение. Сначала сделай читающие версии совместимыми, затем разреши запись нового состояния. Удаление используемого значения требует миграции записей и проверки SQL плана своей СУБД.

Поле enum удобно тем, что ошибка имени видна при компиляции. Проверка допустимого перехода, например из `DRAFT` в `PUBLISHED`, остаётся бизнес-правилом приложения: само перечисление переходы не описывает.
