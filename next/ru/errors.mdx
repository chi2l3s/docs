Ошибка Volan обычно указывает на определённый этап. Диагностика схемы появляется до генерации; ошибка компиляции может говорить о несовпадении клиента и runtime; ошибка подключения — о конфигурации; constraint exception — о данных или текущем состоянии базы.

Сначала установи, на каком этапе произошёл сбой. Это быстрее, чем менять схему, драйвер и URL одновременно. На границе HTTP возвращай понятный ответ приложения, а подробную причину сохраняй в диагностике.

| Исключение | Действие |
|---|---|
| VolanConfigurationException | Проверь JDBC URL, JAR диалекта и драйвер |
| VolanValidationException | Заполни обязательные поля записи |
| VolanNotFoundException | Обработай отсутствие записи в OrThrow |
| VolanRelationNotLoadedException | Добавь include или не читай связь |
| VolanFieldNotSelectedException | Выбери поле до чтения |
| VolanUniqueConstraintException | Обработай повтор бизнес-ключа |
| VolanForeignKeyException | Проверь целевую запись и delete action |
| VolanConstraintException | Проверь NOT NULL или CHECK |
| VolanMappingException | Согласуй данные с типами и enum схемы |
| VolanConnectionException | Проверь доступность БД и размер пула |
| VolanTimeoutException | Проверь timeout пула/statement и нагрузку |
| VolanTransactionException | Повторяй только при retryable и безопасном callback |
| VolanQueryException | Проверь cause и generated/ручной SQL |
| VolanUnsupportedException | Измени неподдерживаемую форму запроса |
Диагностика схемы использует E00xx для lexer, E01xx для parser и E02xx для semantic validation. Сообщение содержит имя файла, фрагмент исходника и исправление, когда оно очевидно. Например, E0209 — отсутствие primary key, E0224 — references не уникальны. Ограничения provider могут вызвать E0235.

При ошибке generated code сначала согласуй версии generator/runtime/plugin и повтори генерацию. Не исправляй сгенерированные файлы вручную. Отсутствие таблицы означает неприменённый DDL либо подключение к другой БД.

Java async передаёт ошибки через CompletionException/ExecutionException; читай cause. Различай бизнес-конфликт, временную недоступность и retryable transaction failure. Не повторяй все исключения автоматически.

Edited/missing/unfinished migration history останавливает deployment; это не обычная временная ошибка запроса. Следуй [восстановлению](/next/ru/migrations).

## Отсутствующая строка и конфликт записи

`findUnique` может вернуть null без ошибки: строка просто не найдена. `findUniqueOrThrow` превращает это состояние в `VolanNotFoundException`. Выбирай вариант по смыслу операции и обрабатывай отсутствие записи один раз на границе сервиса.

При `VolanUniqueConstraintException` проверь бизнес-ключ и конкурентное выполнение. Предварительный `exists` не гарантирует, что другая транзакция не вставит строку между проверкой и create. Ограничение БД остаётся последней проверкой уникальности; приложение должно уметь объяснить такой конфликт.

## Ошибка загрузки результата

`VolanRelationNotLoadedException` означает, что код читает связь, которую query не загрузил. `VolanFieldNotSelectedException` означает чтение пропущенного поля проекции. В обоих случаях исправь форму запроса либо состав DTO, а не добавляй повтор всего запроса вслепую.

`VolanMappingException` требует сравнить тип поля и фактические данные. Причиной может быть значение enum вне схемы или текст времени, записанный ручным SQL в несовместимом формате. Сохрани минимальный воспроизводимый пример со схемой, видом операции и отредактированными данными.

## Порядок проверки подключения

Проверь наличие JDBC URL, его provider, модуль диалекта и драйвер. Затем — доступность сервера и credentials. Для SQLite проверь полный путь файла и рабочий каталог. Если ошибка говорит, что таблица не существует, убедись, что миграции применены именно к этой базе.

Не делай общий retry для всех исключений. Ошибка поля, незагруженная связь или неверная схема не исправятся повторным запросом. Для временных сбоев записи учитывай, мог ли предыдущий запрос уже завершиться, и проверяй результат по бизнес-ключу, когда это необходимо.
