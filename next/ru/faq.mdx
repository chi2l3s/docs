Здесь собраны вопросы, которые чаще всего возникают между установкой и первым настоящим endpoint. Каждый ответ объясняет поведение ORM и указывает, где разобрать его на примере.

## Нужно ли сначала устанавливать CLI?

Для приложения нужны библиотеки, диалект и JDBC-драйвер. CLI удобен для работы со схемой, но не обязателен для [Первого запроса](/next/ru/quickstart): там генерация вызывается сборкой. `volan init` создаёт `schema.volan`, а структуру Gradle/Maven-приложения настраиваешь отдельно.

## Почему схема есть, а таблицы нет?

Схема описывает модель и generated API. Генератор не подключается к базе, поэтому успешная генерация не создаёт таблицу. Примени DDL или [миграцию](/next/ru/migrations) к тому же JDBC URL, который использует клиент. Для SQLite проверь также рабочий каталог: относительный путь может открыть другой файл.

## Зачем Kotlin plugin в Java-приложении?

Клиент генерируется в Kotlin и должен быть скомпилирован до использования из Java. `javaFriendly = true` добавляет удобные getters, setters и callbacks. Java-код приложения остаётся Java; Kotlin-компилятор обслуживает generated sources. Полная последовательность есть в [Сборке](/next/ru/build).

## Почему код нового CLI не компилируется с alpha.2?

CLI 1.0.0 генерирует API 1.0.0. Runtime alpha.2 может не содержать нужные методы. Используй совпадающий генератор либо обнови библиотеки и плагин вместе до 1.0.0. Обновление CLI само не меняет dependencies приложения; границы поставок описаны в [Версиях](/next/ru/versions).

## Почему findUnique вернул null?

Это нормальный результат, когда строка не найдена. Проверь ключ и выбранную базу, затем обработай отсутствие записи по правилам приложения. Если операция требует существующую строку, используй `findUniqueOrThrow` и обработай not-found на границе сервиса. Для списка нет совпадений означает пустой список.

## Почему name = null обновляет запись, а отсутствие name — нет?

Форма update различает два намерения. Не присваивать поле означает сохранить текущий столбец. Присвоить null означает записать SQL NULL, что допустимо только для nullable-поля. В форме create пропущенное поле может использовать default базы, если он описан и поддерживается.

## Почему чтение posts вызывает исключение?

Запрос не загрузил связь через include. Это отличается от пустого списка публикаций: пустой список возможен после явной загрузки. Добавь include, если данные нужны, или убери чтение связи из DTO. Volan не выполняет lazy query из getter; подробности есть в [Связях](/next/ru/relations).

## Include всё равно делает несколько запросов?

Да. Runtime читает связанные ключи batches, а many-to-many дополнительно читает join table и целевые строки. Это устраняет запрос на каждого родителя, но не обещает один SQL statement для любого include. Размер batch, глубина и ветви влияют на число statements. `take` внутри include также не гарантирует top-N для каждого родителя.

## Можно вернуть generated entity как JSON?

Serializer может обратиться ко всем getters, включая незагруженные связи. Собери DTO из выбранных скалярных полей: состав ответа будет явным и не потребует данных, которых нет в результате. Проекция помогает ограничить колонки ещё в запросе.

## Можно использовать Spring @Transactional?

Аннотация сама по себе не доказывает присоединение Volan к транзакции Spring. Для связанных операций используй callback клиента `db.transaction` и выполняй запросы через `tx`. Не отправляй отдельные операции этого callback на другой поток. Интеграция lifecycle разобрана в [Фреймворках](/next/ru/frameworks).

## Корутины делают JDBC неблокирующим?

JDBC по-прежнему занимает worker. `suspendQuery` освобождает вызывающую корутину, а запрос переносит на dispatcher. В Volan 1.0 отмена запрашивает `Statement.cancel()` и ждёт cleanup корутины, но не отменяет уже начавшийся commit. Для Java future cancellation и cleanup происходят в разные моменты. См. [Async](/next/ru/async).

## Можно просто повторить упавшую миграцию H2?

Не автоматически: DDL мог уже сделать implicit commit. Прочитай журнал и фактическую структуру, восстанови исходную цель, затем заверши запись истории. `markApplied` не выполняет SQL за тебя. У interrupted push есть отдельный механизм resolve, подробно описанный в [Миграциях](/next/ru/migrations).

## Можно перейти с SQLite на PostgreSQL без изменений?

Проверь типы, defaults, фильтры и SQL миграций. Один и тот же клиентский сценарий может использовать разные формы хранения. В частности, SQLite не поддерживает Decimal и scalar arrays. Замени provider, зависимости и URL согласованно и протестируй переход на целевой БД. Сравнение есть в [СУБД](/next/ru/databases).

## Volan уже стабилен для любого проекта?

Решение зависит от нужных операций и целевой базы. Начни с небольшого воспроизводимого сценария, прочитай [Ограничения](/next/ru/limitations), зафиксируй версии и проверь свои запросы и миграции. Документация показывает текущие гарантии, а не обещание поддержки любой нагрузки.
