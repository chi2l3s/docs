`where` описывает, какие строки нужны приложению. Внутри блока доступны поля конкретной модели; условия собираются в SQL, а значения передаются параметрами. Несколько условий подряд означают `AND`: строка должна выполнить каждое из них.

Ниже используются открытый клиент `db` и [схема User/Post](/next/ru/schema). Фрагменты можно выполнять после создания таблиц и тестовых записей. Отбор по связям не требует загружать их через include.

## Строка, число и набор значений

| Условие | Смысл |
| --- | --- |
| `eq`, `notEq` | Равно или не равно |
| `gt`, `gte`, `lt`, `lte` | Больше, не меньше, меньше, не больше |
| `between(lower, upper)` | Обе границы включены |
| `oneOf(values)`, `notOneOf(values)` | Входит или не входит в набор |
| `contains`, `startsWith`, `endsWith` | Подстрока, начало, окончание строки |
| `isNull()`, `isNotNull()` | Отсутствие или наличие значения |

Операторы зависят от типа поля. Числа и временные типы поддерживают диапазоны. Enum и boolean имеют условия равенства и наборов; для enum не предлагается `gt`. Не нужно сравнивать статус с числом, чтобы выразить допустимые состояния.

```kotlin
val posts = db.post.findMany {
    where {
        views.between(100, 1000)
        title contains "Volan"
    }
    orderBy { id.asc() }
    take = 20
}
```

Здесь публикация должна одновременно иметь от 100 до 1000 просмотров и нужную подстроку в заголовке. Типизированный фильтр не добавляет скрытую проверку владельца: если публикации доступны только определённому автору, включи `authorId` в условие приложения.

## Регистр и null

```kotlin
val users = db.user.findMany {
    where {
        email.ignoringCase() endsWith "@example.org"
        name.isNotNull()
    }
    orderBy { id.asc() }
    take = 20
}
```

`ignoringCase()` действует на `eq`, `notEq`, `contains`, `startsWith`, `endsWith`. Он не меняет сравнение `oneOf` / `notOneOf`. Поведение регистра зависит от базы; стандартное преобразование SQLite работает с ASCII. Проверь реальные алфавиты своих данных перед обещанием поиска без учёта регистра.

SQL `NULL` проверяется специальным условием, а не строкой `"null"` и не `eq null`. Отрицание `name eq "Alice"` также не означает «включить все NULL-имена»: в SQL у NULL своя логика. Если отсутствующие значения должны попасть в результат, добавь явную ветвь `isNull()`.

## `or`, `and`, `not`

```kotlin
val users = db.user.findMany {
    where {
        email endsWith "@example.org"
        or {
            name eq "Alice"
            name.isNull()
        }
        not { email startsWith "blocked" }
    }
    orderBy { id.asc() }
}
```

Запрос требует подходящий домен email, затем принимает имя Alice **или** отсутствие имени, затем исключает email с заданным началом. Внешние условия объединяются через AND; внутри `or` достаточно одной ветви. `and` помогает сгруппировать несколько совместных условий внутри альтернативы, а `not` отрицает весь вложенный блок.

Пустая DSL-группа не служит запретом выборки: если приложение не добавило условия, защитного фильтра не появится. Проверяй обязательные параметры доступа до построения запроса.

## Фильтры по связям

```kotlin
val authors = db.user.findMany {
    where { posts { some { views gt 100 } } }
    orderBy { id.asc() }
}
val posts = db.post.findMany {
    where { author { matches { email endsWith "@example.org" } } }
    orderBy { id.asc() }
}
```

`some` означает хотя бы одного подходящего ребёнка; `none` — отсутствие подходящих детей; `every` — отсутствие детей, нарушающих условие. Поэтому `every` выполняется и для пустого списка. Если нужны пользователи, у которых публикации обязательно есть, вырази наличие через `some`.

На to-one связях используются `matches` и `notMatches`. Все эти условия отбирают родительские строки. Они не заполняют свойства связей и не ограничивают автоматически другой include: [загрузка связей](/next/ru/relations) задаётся отдельно.

## Та же логика в Java

```java
var users = db.getUser().findMany(q -> {
    q.where(w -> {
        w.getEmail().endsWith("@example.org");
        w.or(alternative -> {
            alternative.getName().eq("Alice");
            alternative.getName().isNull();
        });
    });
    q.orderBy(o -> o.getId().asc());
    q.setTake(20);
});
```

Getters дают поля для фильтра, callbacks открывают группы. Значения по-прежнему передаются параметрами. Для собственного SQL этот же принцип нужно соблюдать явно через [rawQuery](/next/ru/querying/raw-sql).
