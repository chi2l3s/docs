Рабочему сервису нужен понятный порядок запуска: проверить конфигурацию, привести базу к нужной версии, открыть общий клиент и только затем принимать запросы. Если эти шаги перемешаны, ошибка миграции может появиться уже после приёма трафика.

Ниже разобраны решения, которые нужно принять для приложения на Volan. Они относятся к соединениям, структуре БД и обращению с результатами; конкретный способ хранения конфигурации и запуска задачи развёртывания выбирает приложение.

## Конфигурация подключения

Подключённый сгенерированный клиент получает JDBC URL и credentials через builder. `env("DATABASE_URL")` в схеме не заставляет клиент автоматически читать все настройки приложения. Проверь обязательные значения на старте, чтобы неверная конфигурация обнаружилась до первого пользовательского запроса.

Установи runtime, подходящий диалект и JDBC-драйвер. Если уже есть DataSource приложения, используй его и сохрани одного владельца пула. Для встроенного пула держи один общий клиент. Не открывай новый клиент для каждой строки или каждого HTTP-запроса.

## Настройки builder и владелец пула

Эти параметры относятся к `VolanClient.builder()` в Kotlin и Java. Значения задаются перед `build()`; уже открытый пул через builder не перенастраивается.

| Метод | Без явного значения | Что настраивает |
| --- | --- | --- |
| `url(String)` | URL отсутствует | JDBC URL; обязателен для встроенного пула |
| `username(String?)`, `password(String?)` | `null` | Credentials, передаваемые встроенному пулу |
| `maxPoolSize(Int)` | `10` | Запрошенное максимальное число соединений |
| `connectionTimeout(Long)` | `30_000L` мс | Ожидание свободного соединения, а не время выполнения SQL |
| `poolName(String)` | `"volan"` | Имя встроенного пула |
| `asyncExecutor(Executor)` | `ForkJoinPool.commonPool()` | Выполнение Java async; executor принадлежит приложению |
| `dataSource(DataSource)` | Не задан | Подключение к существующему пулу приложения |
| `dialect(Dialect)` | Выбор по JDBC URL | Явный диалект, если он не выбирается по URL |

При `dataSource(...)` Volan не создаёт свой пул. Настрой размер, credentials и таймауты на переданном DataSource: параметры встроенного пула их не заменяют. Для выбора диалекта всё равно нужен `url(...)` либо `dialect(...)`; DataSource сам по себе не выбирает SQL-диалект. Закрытие клиента не закрывает переданный DataSource или executor.

Для встроенного пула `close()` клиента закрывает принадлежащий ему пул. Не передавай одному компоненту владение пулом, если другой компонент всё ещё использует его соединения.

Для SQLite встроенный пул использует одно соединение независимо от положительного `maxPoolSize`. Это относится и к файловой базе, и к `:memory:`.

## Нагрузка и ограничения

Определи максимальный размер страницы и разрешённые includes на уровне сервиса. Пользовательский параметр `take` не должен бесконтрольно превращаться в чтение всей таблицы. Проекция помогает возвращать только нужные поля, а явный DTO фиксирует состав ответа.

Пул и workers обслуживают один бюджет БД. Учитывай несколько экземпляров сервиса и число соединений каждого. Таймаут получения соединения, SQL execution и ожидания HTTP-клиента решают разные задачи; один coroutine timeout не заменяет остальные.

## Совместимость deployment

Проверь migration history перед применением, затем отдельно оцени structural drift. История отвечает, какие файлы применены; drift — соответствует ли фактическая структура ожидаемой. Ручное изменение БД может не менять history, поэтому одна проверка не заменяет другую.

При постепенном обновлении несколько версий приложения могут работать одновременно. Планируй изменение таблиц так, чтобы старый код выдержал переходный период. Например, удаление колонки до остановки старой версии ломает её запросы независимо от типобезопасности нового клиента.

## Завершение работы

Сначала прекрати приём новых задач, затем дождись активных запросов и транзакций. Закрой клиент после их завершения; после этого заверши собственные executors, DataSources и registries в соответствии с их владельцами. Не считай cancelled future доказательством того, что JDBC cleanup уже закончился.

Данные в приватной memory-базе исчезают вместе с её соединением. Для данных, которые должны пережить перезапуск, используй файл или серверную БД и проверяемую процедуру резервного копирования. Для nontransactional DDL заранее подготовь способ сравнить и восстановить частично изменённую структуру.
