Здесь собраны вопросы, которые чаще всего возникают между установкой и первым настоящим endpoint. Каждый ответ объясняет поведение ORM и указывает, где разобрать его на примере.

## Нужно ли сначала устанавливать CLI?

Приложению нужны библиотеки, диалект и JDBC-драйвер. В [Первом запросе](/v0.1.0-alpha.1/ru/quickstart) генерация вызывается сборкой. Необязательный CLI из тега предоставляет pull/push и не создаёт проект сборки.

## Почему схема есть, а таблицы нет?

Схема описывает модель и generated API. Генератор не подключается к базе, поэтому успешная генерация не создаёт таблицу. Примени DDL или [миграцию](/v0.1.0-alpha.1/ru/migrations) к тому же JDBC URL, который использует клиент.

## Зачем Kotlin plugin в Java-приложении?

Клиент генерируется в Kotlin и должен быть скомпилирован до использования из Java. `javaFriendly = true` добавляет удобные getters, setters и callbacks. Java-код приложения остаётся Java; Kotlin-компилятор обслуживает generated sources. Полная последовательность есть в [Сборке](/v0.1.0-alpha.1/ru/build).

## Почему код нового CLI не компилируется с alpha.1?

Preview CLI генерирует API alpha.3. Runtime alpha.1 не обязан иметь все методы этого API. Используй совпадающий генератор alpha.1 либо полный staged alpha.3 набор. Обновление CLI само не меняет dependencies приложения; границы поставок описаны в [Версиях](/v0.1.0-alpha.1/ru/versions).

## Почему findUnique вернул null?

Это нормальный результат, когда строка не найдена. Проверь ключ и выбранную базу, затем обработай отсутствие записи по правилам приложения. Если операция требует существующую строку, используй `findUniqueOrThrow` и обработай not-found на границе сервиса. Для списка нет совпадений означает пустой список.

## Почему name = null обновляет запись, а отсутствие name — нет?

Форма update различает два намерения. Не присваивать поле означает сохранить текущий столбец. Присвоить null означает записать SQL NULL, что допустимо только для nullable-поля. В форме create пропущенное поле может использовать default базы, если он описан и поддерживается.

## Почему чтение posts вызывает исключение?

Запрос не загрузил связь через include. Это отличается от пустого списка публикаций: пустой список возможен после явной загрузки. Добавь include, если данные нужны, или убери чтение связи из DTO. Volan не выполняет lazy query из getter; подробности есть в [Связях](/v0.1.0-alpha.1/ru/relations).

## Include всё равно делает несколько запросов?

Да. Runtime читает связанные ключи batches, а many-to-many дополнительно читает join table и целевые строки. Это устраняет запрос на каждого родителя, но не обещает один SQL statement для любого include. Размер batch, глубина и ветви влияют на число statements. `take` внутри include также не гарантирует top-N для каждого родителя.

## Можно вернуть generated entity как JSON?

Serializer может обратиться ко всем getters, включая незагруженные связи. Собери DTO из выбранных скалярных полей: состав ответа будет явным и не потребует данных, которых нет в результате. Проекция помогает ограничить колонки ещё в запросе.

## Можно использовать Spring @Transactional?

Аннотация сама по себе не доказывает присоединение Volan к транзакции Spring. Для связанных операций используй callback клиента `db.transaction` и выполняй запросы через `tx`. Не отправляй отдельные операции этого callback на другой поток. Интеграция lifecycle разобрана в [Фреймворках](/v0.1.0-alpha.1/ru/frameworks).

## Корутины делают JDBC неблокирующим?

Нет. JDBC занимает рабочий поток. В Kotlin-сервисе используй перенос средствами фреймворка, в Java — futures с отдельным executor. В alpha.1 нет coroutine-адаптера Volan и отмены активного statement. Доступное поведение разобрано в [Async](/v0.1.0-alpha.1/ru/async).

## Можно подключить SQLite к alpha.1?

Нет. SQLite-диалект и reader миграций появились в alpha.2. Обнови генератор, runtime и связанные библиотеки вместе, осознанно поменяй provider и драйвер и проверь модель данных.

## Volan уже стабилен для любого проекта?

Это alpha до 1.0. Решение зависит от нужных операций и целевой базы. Начни с небольшого воспроизводимого сценария, прочитай [Ограничения](/v0.1.0-alpha.1/ru/limitations), зафиксируй версии и проверь свои запросы и миграции. Документация показывает текущие гарантии, а не обещание поддержки любого workload.
