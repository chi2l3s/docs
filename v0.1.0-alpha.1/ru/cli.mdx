CLI из тега `v0.1.0-alpha.1` — инструмент синхронизации базы. Он предоставляет `db pull` и `db push` и требует Java 17+. В [Установке](/v0.1.0-alpha.1/ru/installation) показано, как собрать этот тег и добавить launcher в PATH.

```bash
volan --help
volan db pull --url jdbc:postgresql://localhost:55433/volan_example --stdout
volan db push --schema schema.volan --url jdbc:postgresql://localhost:55433/volan_example --dry-run
volan db push --schema schema.volan --url jdbc:postgresql://localhost:55433/volan_example
```

## Сначала прочитай изменение

`pull --stdout` печатает представимую структуру базы. Без stdout он записывает файл схемы; `--force` разрешает заменить существующий. Сначала сохраняй интроспекцию отдельно, чтобы случайно не заменить своё описание модели.

`push --dry-run` показывает SQL и предупреждения без применения. Выполни его на нужной базе разработки и проверь удаления, новые обязательные поля и ограничения. `--accept-data-loss` принимает изменения с предупреждениями, но не делает их обратимыми.

## Подключение и пути

По умолчанию используется `schema.volan`. Push читает URL datasource, если он не переопределён `--url`. Pull использует `--url` либо `DATABASE_URL`. Для PostgreSQL передай `DATABASE_USER` и `DATABASE_PASSWORD` через окружение.

URL должен иметь JDBC-формат. Перед применением проверь цель. Направление сравнения и ограничения интроспекции разобраны в [Синхронизации](/v0.1.0-alpha.1/ru/sync).

## Команды этой версии

В alpha.1 нет `init`, `generate`, `format`, `validate`, `migrate` и `--resolve`. Генерируй клиент программой alpha.1 из [Первого запроса](/v0.1.0-alpha.1/ru/quickstart). Версионируемые SQL-файлы применяются через [API миграций](/v0.1.0-alpha.1/ru/migrations).

Preview CLI alpha.3 имеет больше команд и генерирует более новый API. Переключение документации не обновляет зависимости приложения. Используй инструмент и генератор, соответствующие его версии.

## Как выбирается адрес базы

Для `db push` приоритет такой:

1. Явный `--url`.
2. URL из datasource файла схемы: строка либо значение переменной, указанной в `env(...)`.
3. `DATABASE_URL`, если предыдущие источники не дали значения.

`db pull` не загружает существующую схему для подключения. Он использует `--url`, затем `DATABASE_URL`; `--schema` задаёт путь выходного файла. Если в datasource используется `env("APP_DATABASE_URL")`, для pull всё равно передай `--url` или установи `DATABASE_URL`.

Пустая строка не считается отсутствующим значением: выбранный пустой URL не переключает команду на следующий источник и не проходит проверку JDBC. `DATABASE_USER` и `DATABASE_PASSWORD` передаются драйверу отдельно. Наличие env в схеме также не заставляет builder клиента приложения читать URL автоматически.

## Вывод и запись файлов

| Режим | stdout | Файлы и база |
| --- | --- | --- |
| `db pull --stdout` | Текст схемы | Файл схемы не записывается |
| `db pull` | `Wrote ...` после успеха | Создаёт новый файл; существующий сохраняется без `--force` |
| `db push --dry-run` | SQL плана либо `Schema is up to date.` | План не применяется; команда подключается к базе |
| `db push` | Число изменений либо `Schema is up to date.` | Применяет план при выполнении его проверок |

Предупреждения dry-run идут в stderr отдельно от SQL. Нулевой код завершения означает успех команды, но не обязательно наличие изменений: отсутствие drift также успешно. Для CI обрабатывай ненулевой код как ошибку и сохраняй stderr, а не определяй успех по наличию строки в stdout.

`--force` разрешает заменить файл результата pull. `--accept-data-loss` разрешает применить план с предупреждениями. Это флаги разных операций: ни один из них не является общим режимом игнорирования ошибок.
