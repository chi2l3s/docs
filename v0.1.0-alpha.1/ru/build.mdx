Сборка читает `schema.volan`, генерирует Kotlin и компилирует его вместе с приложением. Она не подключается к базе и не применяет миграции. Полная конфигурация Gradle и программа генерации находятся в [Первом запросе](/v0.1.0-alpha.1/ru/quickstart).

## Генерация как часть сборки

Подключи `volan-codegen:0.1.0-alpha.1` в отдельный source set `generator`. Зарегистрируй `build/generated/volan` как исходники Kotlin main и добавь зависимость `compileKotlin` от `generateClient`. После компиляции Java обращается к полученным классам через getters и callbacks.

```java
var source = new SourceFile("schema.volan", Files.readString(Path.of(args[0])));
VolanGenerator.writeTo(SchemaLoader.loadOrThrow(source), Path.of(args[1]));
```

Полные imports и точка входа есть в первом примере. `args[0]` — путь к схеме, `args[1]` — каталог результата. Неверная модель останавливает генерацию с диагностикой. После успешной генерации компиляция обнаруживает обращения к удалённым полям.

## Зависимости и владение файлами

Runtime и диалект выравниваются BOM alpha.1. Codegen подключается только для сборки с той же явно указанной версией. Держи результат генерации отдельно от написанного вручную кода: генератор владеет своими файлами и удаляет устаревшие.

В alpha.1 нет опубликованного Gradle- или Maven-плагина Volan. Не переноси сюда конфигурацию плагина alpha.3. Генератор нужной версии можно вызвать из своей задачи Gradle или шага Maven, затем скомпилировать полученный Kotlin.

## Если клиент выглядит устаревшим

После изменения схемы сначала запусти генерацию и компиляцию. Проверь путь к схеме и регистрацию каталога исходников. Два каталога генерации могут оставить классы с одинаковыми именами; неверно настроенная инкрементальная сборка может сохранить старый bytecode.

Не исправляй сгенерированный файл вручную, чтобы скрыть несовместимость. Меняй схему или код приложения. Если генератор выпустил методы, которых нет в runtime, сначала сравни версии. Граница релизов описана в [совместимости](/v0.1.0-alpha.1/ru/versions).

## Проверка базы — отдельный этап

Успешная сборка не гарантирует существование таблицы. Генерация проверяет описание, а не живую БД. Выполни интеграционные запросы на нужной СУБД и примени [миграции](/v0.1.0-alpha.1/ru/migrations) до запуска кода, требующего новые колонки.
