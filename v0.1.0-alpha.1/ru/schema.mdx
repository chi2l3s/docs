`schema.volan` отвечает на несколько конкретных вопросов: какие записи есть в приложении, какие поля обязательны, что делает запись уникальной и как модели связаны друг с другом. Из этого описания Volan создаёт API запросов и записи.

Ниже пользователь может иметь много публикаций. У каждой публикации есть один обязательный автор. Эту схему используют примеры [Запросов](/v0.1.0-alpha.1/ru/queries), [Связей](/v0.1.0-alpha.1/ru/relations) и [Транзакций](/v0.1.0-alpha.1/ru/transactions). Если расширяешь первый quickstart, добавь модель `Post`, затем обнови клиент и структуру БД.

```prisma
datasource db {
  provider = "postgresql"
  url = env("DATABASE_URL")
}
generator client {
  provider = "volan-kotlin"
  package = "org.example.generated"
  javaFriendly = true
}
model User {
  id Int @id @default(autoincrement())
  email String @unique
  name String?
  posts Post[]
}
model Post {
  id Int @id @default(autoincrement())
  title String
  views Int @default(0)
  authorId Int
  author User @relation(fields: [authorId], references: [id], onDelete: Cascade)
}
```

## Поля и ключи

`String` — обязательное поле, `String?` — nullable, `Post[]` — список связанных записей. Nullable-списки и вложенные списки запрещены. Скалярные типы: String, Int, Long, Float, Double, Decimal, Boolean, DateTime, Date, Time, Json, Bytes, Uuid.

| Атрибут | Назначение |
|---|---|
| `@id`, `@@id([a,b])` | Простой или составной первичный ключ |
| `@unique`, `@@unique([a,b])` | Уникальное ограничение |
| `@@index([a,b])` | Индекс |
| `@map("column")`, `@@map("table")` | Имена клиента и SQL могут отличаться |
| `@default(...)` | Совместимый литерал, enum, now(), uuid(), autoincrement() |
| `@updatedAt` | Timestamp, обновляемый runtime |
| `@relation(...)` | Связь и внешний ключ |
| `@@ignore` | Не генерировать клиент таблицы без подходящего ключа |

Нужен ровно один первичный ключ, кроме ignored-моделей. Типы внешнего ключа и уникального ключа назначения должны совпадать. Для связи один к одному нужен уникальный внешний ключ. SetNull требует nullable-полей. Неявная связь многие ко многим задаётся парными списками без стороны с внешним ключом.

Нативные типы `@db` доступны только для PostgreSQL. `@@fulltext` не добавляет типизированный поисковый API. Не называй скалярное поле `count` или ключевым словом Kotlin; выбери безопасный alias с mapping.

## Генерация

Генератор `volan-codegen:0.1.0-alpha.1` читает и проверяет схему, затем выпускает Kotlin. В [Первом запросе](/v0.1.0-alpha.1/ru/quickstart) эта программа включена в компиляцию. CLI для базы в alpha.1 не генерирует и не форматирует исходники.

Генерация не открывает базу. `env("DATABASE_URL")` разрешается при операции, которой нужно соединение. Комментарии `//` и документация `///` сохраняются при форматировании; block comments недопустимы. Атрибуты поля записываются на его строке.

[Полный синтаксис и диагностики](https://github.com/thirtyeighttwentysix/volan/blob/v0.1.0-alpha.1/docs/schema-language.md).

## Почему у связи два поля

В `Post` поле `authorId` — скалярный внешний ключ, который хранится в таблице. Поле `author` описывает связь в API клиента. На стороне пользователя `posts` описывает обратный список. Этот список не превращается в отдельную колонку таблицы `User`.

`fields: [authorId]` говорит, где лежит ключ, а `references: [id]` — на какое уникальное поле автора он ссылается. При `onDelete: Cascade` удаление пользователя приводит к удалению его публикаций силами внешнего ключа БД. Выбирай это поведение по правилам приложения: если публикации должны сохраняться, модель связи потребуется изменить.

## Обязательное, nullable и default

У `email String` нет default, поэтому новая запись должна передать email. У `name String?` допустим SQL NULL. У `views Int @default(0)` пропущенное значение может быть заполнено default базы. В форме update отсутствие присваивания означает «оставить поле как есть», а явное `name = null` означает «очистить имя».

Default не является проверкой бизнес-правила. Например, начальные `views = 0` не запрещают вручную записать отрицательное число. Валидация приложения и ограничения базы дополняют типы схемы.

## Имена клиента и таблиц

Mapping помогает подключить существующую базу, не заставляя код повторять неудобные SQL-имена. `@map` меняет имя колонки, `@@map` — таблицы; в Kotlin и Java остаётся имя из модели. Пользуйся этим и при конфликте с зарезервированными именами: alias в клиенте может быть безопасным, даже если таблицу переименовать нельзя.

Изменение имени в схеме не доказывает, что база должна выполнить rename. План синхронизации может увидеть удаление и добавление. Если данные нужно сохранить, подготовь явную проверенную миграцию с SQL rename.
