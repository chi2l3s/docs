Используй @db.Type только с PostgreSQL. Это SQL-тип; JVM-тип задаётся scalar-полем.

```prisma
model Reading {
  id Int @id
  label String @db.VarChar(120)
  value Decimal @db.Decimal(12, 4)
  at DateTime @db.Timestamptz(6)
}
```

Каталог нормализации migration/introspection: BigInt, Bit, Boolean, ByteA, Char, Citext, Date, Decimal, DoublePrecision, Inet, Integer, Json, JsonB, Money, Oid, Real, SmallInt, Text, Time, Timestamp, Timestamptz, Timetz, Uuid, VarBit, VarChar, Xml. Имена сравниваются без учёта регистра. Канонические значения без @db: String→Text, Int→Integer, Long→BigInt, Float→Real, Double→DoublePrecision, Boolean→Boolean, Date→Date, Json→JsonB, Bytes→ByteA, Uuid→Uuid, Decimal→Decimal(65,30), DateTime→Timestamp(3), Time→Time(3).

В 1.0.0 analyzer проверяет namespace/форму атрибута и возможности провайдера, но не гарантирует совместимость любой пары scalar/native и диапазона SQL-аргументов. Каталог выше описывает нормализацию, а не исчерпывающую проверку SQL. Проверяй получившийся DDL и чтение драйвером; PostgreSQL отклонит неверный тип/размер. Расширения вроде citext должны существовать в БД.
