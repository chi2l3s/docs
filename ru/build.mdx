Сгенерированный клиент — такая же часть сборки, как классы приложения. Когда меняется `schema.volan`, сборка должна обновить клиент до компиляции кода, который его использует. Тогда ошибка в имени поля обнаружится при компиляции, а не после запуска сервиса.

Для опубликованной alpha.2 используй полную конфигурацию на странице [Первый запрос](/ru/quickstart). Ниже показаны Gradle и Maven плагины alpha.3. Они уже реализованы, но пока требуют artifacts, подготовленных из исходников. Не добавляй их как будто alpha.3 доступна в Central.

## Подготовка alpha.3

Клонируй [репозиторий](https://github.com/thirtyeighttwentysix/volan) и выполни из корня:
```bash
./gradlew publishAllPublicationsToReleaseTestRepository "-Pversion=0.1.0-alpha.3" -PvolanUnsignedLocalPublication --no-configuration-cache
```

Команда создаёт `build/release-repository`, не публикуя artifacts в Central. Генератор, плагины и runtime должны использовать этот репозиторий и одну версию. Локальная `0.1.0-alpha.3` обозначает кандидат, а не опубликованный релиз. Версия main по умолчанию — `0.1.0-alpha.3-SNAPSHOT`.

## Gradle

Это файлы проверяемого [Gradle-примера](https://github.com/thirtyeighttwentysix/volan/tree/main/plugin-smoke/gradle). Нужны Java 17+, Kotlin/JVM main sources; проверяется Gradle 9.8.0. `settings.gradle.kts`:
```kotlin
pluginManagement {
    repositories {
        val staged = providers.gradleProperty("volanRepository").orNull
        if (staged != null) maven { url = uri(staged) }
        mavenCentral()
        gradlePluginPortal()
    }
    plugins {
        id("io.github.thirtyeighttwentysix.volan") version providers.gradleProperty("volanVersion").getOrElse("0.1.0-alpha.3")
    }
}

dependencyResolutionManagement {
    repositories {
        val staged = providers.gradleProperty("volanRepository").orNull
        if (staged != null) maven { url = uri(staged) }
        mavenCentral()
    }
}
rootProject.name = "volan-gradle-consumer"
```

`build.gradle.kts`:
```kotlin
plugins {
    kotlin("jvm") version "2.4.20"
    id("io.github.thirtyeighttwentysix.volan")
}

val volanVersion = providers.gradleProperty("volanVersion").getOrElse("0.1.0-alpha.3")
dependencies {
    implementation("io.github.thirtyeighttwentysix:volan-dialect-h2:$volanVersion")
    runtimeOnly("com.h2database:h2:2.5.252")
    testImplementation("org.junit.jupiter:junit-jupiter:6.1.3")
    testImplementation("io.github.thirtyeighttwentysix:volan-coroutines:$volanVersion")
    testImplementation("io.github.thirtyeighttwentysix:volan-micrometer:$volanVersion")
    testRuntimeOnly("org.junit.platform:junit-platform-launcher:6.1.3")
    testRuntimeOnly("org.slf4j:slf4j-nop:2.0.20")
}
kotlin { compilerOptions { jvmTarget.set(org.jetbrains.kotlin.gradle.dsl.JvmTarget.JVM_17) } }
tasks.withType<JavaCompile>().configureEach { options.release.set(17) }
tasks.test { useJUnitPlatform() }
```

Используй схему H2 со страницы [Примеры](/ru/examples). Выполни `./gradlew -p plugin-smoke/gradle test "-PvolanRepository=file:///absolute/path/build/release-repository"`. Для Windows URI имеет вид `file:///D:/Projects/Volan/build/release-repository`.

Плагин добавляет совпадающий runtime, регистрирует Kotlin-файлы и связывает `volanGenerate` с компиляцией. Диалект и JDBC-драйвер добавь отдельно. Пути меняются через `volan { schemaFile.set(layout.projectDirectory.file("db/schema.volan")); outputDirectory.set(layout.buildDirectory.dir("generated/client")) }`.

## Maven

Нужны Maven 3.9+ и Java 17+. Полный POM [Maven-примера](https://github.com/thirtyeighttwentysix/volan/tree/main/plugin-smoke/maven):
```xml
<project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>
  <groupId>example</groupId><artifactId>volan-maven-consumer</artifactId><version>1.0</version>
  <properties>
    <volan.version>0.1.0-alpha.3</volan.version>
    <kotlin.version>2.4.20</kotlin.version>
    <kotlin.compiler.jdkRelease>17</kotlin.compiler.jdkRelease>
    <kotlin.compiler.daemon>false</kotlin.compiler.daemon>
    <kotlin.compiler.incremental>true</kotlin.compiler.incremental>
    <maven.compiler.release>17</maven.compiler.release>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
  </properties>
  <dependencies>
    <dependency><groupId>io.github.thirtyeighttwentysix</groupId><artifactId>volan-runtime</artifactId><version>${volan.version}</version></dependency>
    <dependency><groupId>io.github.thirtyeighttwentysix</groupId><artifactId>volan-dialect-h2</artifactId><version>${volan.version}</version></dependency>
    <dependency><groupId>com.h2database</groupId><artifactId>h2</artifactId><version>2.5.252</version><scope>runtime</scope></dependency>
    <dependency><groupId>org.junit.jupiter</groupId><artifactId>junit-jupiter</artifactId><version>6.1.3</version><scope>test</scope></dependency>
    <dependency><groupId>org.slf4j</groupId><artifactId>slf4j-nop</artifactId><version>2.0.20</version><scope>test</scope></dependency>
  </dependencies>
  <build>
    <plugins>
      <plugin>
        <groupId>io.github.thirtyeighttwentysix</groupId><artifactId>volan-maven-plugin</artifactId><version>${volan.version}</version>
        <executions><execution><goals><goal>generate</goal></goals></execution></executions>
      </plugin>
      <plugin>
        <groupId>org.jetbrains.kotlin</groupId><artifactId>kotlin-maven-plugin</artifactId><version>${kotlin.version}</version>
        <extensions>true</extensions>
      </plugin>
      <plugin><groupId>org.apache.maven.plugins</groupId><artifactId>maven-compiler-plugin</artifactId><version>3.16.0</version></plugin>
      <plugin><groupId>org.apache.maven.plugins</groupId><artifactId>maven-surefire-plugin</artifactId><version>3.5.4</version></plugin>
    </plugins>
  </build>
  <profiles>
    <profile>
      <id>staged</id><activation><property><name>volanRepository</name></property></activation>
      <repositories><repository><id>volan-staged</id><url>${volanRepository}</url></repository></repositories>
      <pluginRepositories><pluginRepository><id>volan-staged</id><url>${volanRepository}</url></pluginRepository></pluginRepositories>
    </profile>
  </profiles>
</project>
```

Запуск: `mvn -f plugin-smoke/maven/pom.xml test -DvolanRepository=file:///absolute/path/build/release-repository`.

Цель `generate` выполняется в `generate-sources`. Даже Java-приложению нужен Kotlin-компилятор для клиента. BOM выравнивает библиотеки, но не версии плагинов. Incremental Kotlin compilation удаляет bytecode удалённых моделей; без неё после удаления модели выполни `mvn clean test`.

Пути Maven по умолчанию: `schema.volan`, `target/generated-sources/volan`. Настройки: `schemaFile` / `outputDirectory` либо `-Dvolan.schemaFile` / `-Dvolan.outputDirectory`.

## Результат генерации

Каталоги генерации принадлежат сборке. Плагины переопределяют output из схемы. Не размещай там код приложения и не меняй `.volan-generated-files`. Генерация удаляет устаревшие собственные файлы, отказывает при коллизиях и ссылках внутри output. Компиляция не меняет БД.

## Что происходит при сборке

Сначала генератор читает текст схемы и проверяет её. Затем записывает модели, репозитории и вспомогательные формы запросов в каталог generated sources. Kotlin-компилятор собирает эти файлы вместе с приложением; Java-компилятор получает доступ к готовым классам клиента. После этого запускаются тесты.

Для этих шагов не нужна работающая база. Генератор не проверяет наличие таблиц и не применяет DDL. Это позволяет собирать приложение в CI без production credentials. Совместимость с реальной структурой базы проверяется миграциями и интеграционными тестами отдельно.

## Когда клиент выглядит устаревшим

Если после изменения схемы новый getter не появился, сначала запусти задачу генерации и компиляцию проекта. Проверь, что сборка читает нужный файл `schemaFile`, а output зарегистрирован в sources. Два разных output-каталога могут оставить одновременно старый и новый клиент с одинаковыми именами.

Не исправляй файлы внутри generated sources вручную: следующая генерация заменит их. Меняй схему или код приложения. При удалении модели проверь и generated source, и старый bytecode: для Maven без incremental Kotlin compilation нужен `clean`.

## Репозитории зависимостей

Gradle ищет build plugin через `pluginManagement`, а библиотеки приложения — через обычные repositories. Maven тоже разделяет `<pluginRepositories>` и `<repositories>`. При локальном staging нужны оба пути: иначе runtime может находиться, а plugin — нет.

Для воспроизводимой сборки generator, runtime и plugin должны относиться к одному релизу. BOM помогает с библиотеками, но не устанавливает версию Maven plugin или Gradle plugin. Фиксируй их явно и обновляй вместе.
