Выполняй связанные записи через `transaction` подключённого клиента.

```kotlin
val created = db.transaction { tx ->
    val user = tx.user.create { email = "transaction@example.org" }
    tx.post.create { title = "Welcome"; authorId = user.id }
    user
}
```

Java использует `db.transaction(tx -> { ...; return result; })` либо `transactionAsync(...).join()` вне другой транзакции.

Весь callback работает на одном потоке и соединении. Нормальное завершение делает commit, исключение — rollback. Вложенная синхронная транзакция создаёт savepoint. Откат DDL — отдельная [гарантия СУБД](/ru/databases), он не следует из транзакционности DML.

## Изоляция и повторы

`Isolation.DEFAULT` использует настройки драйвера. Явные уровни зависят от СУБД; SQLite поддерживает SERIALIZABLE и READ_UNCOMMITTED. По умолчанию используй `RetryPolicy.NONE`. Настроенный retry повторяет весь внешний callback при повторяемой ошибке транзакции: код должен допускать повторное выполнение. Платежи, HTTP, отправку сообщений и другие необратимые эффекты выполняй снаружи.

Из подключённой транзакции нельзя отправлять async или coroutine работу на другой поток. Используй синхронные операции `tx`. Не возвращай future из callback и не запускай в нём дочерние корутины.

Для корутин отправляй целую `transaction` через [suspendQuery](/ru/async). Callback остаётся синхронным. Клиенты поверх bare QueryExecutor не владеют соединением и не предоставляют guards подключённой транзакции.

## Lifecycle

Держи транзакции короткими. Закрывай клиент при остановке приложения после завершения работы. Переданный DataSource остаётся собственностью приложения. Не считай, что Spring `@Transactional` автоматически присоединяет транзакцию Volan.
