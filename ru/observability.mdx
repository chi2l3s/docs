Один вызов репозитория не всегда равен одному SQL statement. `include` может добавить чтение связей, nested write — несколько записей. Чтобы понять, на что уходит время и сколько обращений действительно выполнилось, наблюдай отдельные SQL-команды через `QueryInterceptor`.

Перехватчики и модуль Micrometer доступны в alpha.3. Подключай их с совпадающим runtime из [локальных artifacts](/ru/build). Если метрики не нужны, синхронное ядро работает без Micrometer и корутин.

## Перехватчики

Реализуй `QueryInterceptor.intercept(query: QueryContext, next: Supplier<T>): T`. Регистрация: `VolanClient.builder().interceptor(interceptor)`. Перехватчик должен быть thread-safe и вызвать `next.get()` ровно один раз на том же потоке. Первый зарегистрированный оборачивает остальные; повторный вызов и перенос downstream на другой поток запрещены.

Перехватчики охватывают получение соединения, preparation, binding, execution, mapping и cleanup для generated queries, raw SQL, чтения связей и nested writes. Проверка пула, инициализация диалекта, управление транзакциями и команды миграций напрямую через JDBC не входят в область перехвата.

QueryContext содержит SQL, операцию QUERY/EXECUTE и диалект, но не значения параметров. В ручном SQL могут оставаться чувствительные литералы. Не логируй credentials или SQL без редактирования. Ошибка перехватчика передаётся вызывающему коду и может откатить транзакцию; завершённый autocommit не отменяется. Перехватчики не добавляют условия tenant isolation или soft delete.

## Micrometer

Добавь `io.github.thirtyeighttwentysix:volan-micrometer` и передай MeterRegistry:

```kotlin
import io.github.thirtyeighttwentysix.volan.micrometer.MicrometerQueryInterceptor

val db = VolanClient.builder()
    .url(url)
    .interceptor(MicrometerQueryInterceptor(registry))
    .build()
```

Timer `volan.query` измеряет попытки выполнения statements, включая получение соединения и mapping.

| Tag | Значения |
|---|---|
| dialect | Идентификатор provider |
| operation | query, execute |
| outcome | success, error, cancelled |

SQL, значения параметров и тексты ошибок не становятся metric labels. Include даёт sample на каждый statement; успешный statement в позднее отменённой транзакции остаётся успешным sample. Registry и exporter принадлежат приложению; Volan не закрывает их.

## Как читать измерение

Время `volan.query` включает получение соединения и преобразование строк в объекты. Рост времени может означать медленный SQL, ожидание пула или большой результат. По одному timer нельзя доказать причину: сопоставляй его с метриками пула, размером выдачи и измерениями самой БД.

Если запрос пользователя с публикациями дал несколько samples, это ожидаемо для include. Если sample успешный, он говорит об успешном statement, а не об успешном HTTP-ответе и не о commit всей транзакции. Последующая ошибка может откатить записи, которые раньше выполнились без ошибки.

## Метрики, которые можно сравнивать

Ограниченный набор tags позволяет сравнивать provider, тип операции и исход без создания отдельного time series для каждого пользователя. Не добавляй email, `id`, полный SQL или текст ошибки в labels. Такие значения увеличивают cardinality, а иногда раскрывают данные приложения.

Когда разбираешь конкретный медленный запрос, используй диагностический лог или tracing приложения с подходящим редактированием значений. Для постоянных метрик оставляй небольшие стабильные категории. Registry и его exporter создаёт приложение; клиент только передаёт измерения зарегистрированному перехватчику.

## Ответственность перехватчика

`next.get()` выполняет реальное обращение к БД. Вызови его ровно один раз и верни результат либо передай ошибку наружу. Перехватчик работает в контексте запроса; перенос downstream на другой поток нарушит guards транзакции. Не используй hook как место повторного SQL-запуска.

Для tenant isolation добавляй фильтр в типизированный запрос. Перехватчик наблюдает statement и не превращает произвольный SQL в корректно ограниченный запрос приложения.
